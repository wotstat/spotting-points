# WotStat Spotting Points

Python 2.7 мод для ангара «Мира танков» и WoT. Пункт ModsList открывает
единственное немодальное Scaleform-окно с пятью флагами: габаритные точки,
обзорные точки, точки в UI, направляющие и вращение башни. Все они выключены по
умолчанию, меняются сразу и не сохраняются между запусками.

Геометрия повторяет ангарную часть SpottingUtil из wotstat-debug-utils:
габаритные точки красные, обзорные голубые, направляющие относительно
габаритов корпуса. BBox и направляющие повторяют все 13 полилиний
`showBBoxes` + `showBBoxAlign`: белые границы корпуса и верхней плоскости,
серые диагонали и привязки точек. Из линий только поперечная направляющая
имеет бледный проход, остальные проверяют глубину, как в источнике.
Для сфер два прохода DebugDrawer: бледный без проверки глубины
и яркий с проверкой. Совпадающие обзорные и габаритные точки показываются
голубыми сферами. Отдельный Scaleform-слой `WindowLayer.MARKER` проецирует все
точки в UI, объединяет совпадающие и рисует одинаковые пульсирующие маркеры со
сносками. Все видимые точки подписаны. На каждой стороне сноски размещаются по
возрастанию горизонтального выноса; более длинная линия получает ближайший
свободный слот выше или ниже с предпочтением варианта без пересечения уже
проложенных линий. Hover по точке или сноске выделяет минимальный набор
образующих направляющих жёлтым без проверки глубины: грань с диагоналями для
передней/задней точки, боковую грань с осью и привязками для бортовой, верхнюю
плоскость для верхней и ось склонения с дугой поворота для динамической
орудийной. Боевые вычисления и зависимость debug-utils не входят в мод.

Controller получает выбранный танк через IHangarSpace. 3D-примитивы рисуются
каждый кадр. UI-состав и hover проверяются не чаще 30 раз в секунду в UI-only
режиме, но экранная позиция каждого маркера обновляется нативным
`GUI.HangarVehicleMarker` / `GUI.WGHangarVehicleMarker` через `MatrixProvider`
вместе с рендером камеры. AS3 перекладывает сноски на `ENTER_FRAME`. При смене
машины старые UI-маркеры сразу очищаются; overlay повторяет видимость штатного
ангарного marker view и не обрабатывает hover вне активной 3D-сцены. Статичная
габаритная точка крепления
орудия вычисляется для нулевого поворота башни. Отдельная обзорно-габаритная
точка берётся из живого `GUN_JOINT`, поэтому следует за поворотом. Направляющие
строятся в координатах корпуса и не вращаются. Событие уничтожения ангара
останавливает callback, создание ангара возобновляет его. Выключение и fini
снимают callback; fini снимает подписки и регистрацию ModsList.

Контроллер башни подписывается на события мыши только после включения флага.
Только drag, начатый на collision-части `turret` или `gun`, временно блокирует
штатное вращение камеры. Динамические collision-части 3D-стиля пропускаются до
первой базовой детали танка, поэтому кастомизация не ломает выбор башни или
орудия. Оба типа захвата меняют доступные yaw и pitch с чувствительностью 0,003
радиана на пиксель. Направление фиксировано: движение мыши вправо всегда
уменьшает yaw и вращает башню против часовой стрелки. Углы уважают статичные
оси и пределы дескриптора.

Окно и overlay имеют уникальные alias и SWF, регистрируются соответственно на
`WindowLayer.WINDOW` и `WindowLayer.MARKER` и не изменяют штатные окна или
фабрики других модов.

Источники: ../wot-src-ru (mt-ru, 1.45), ../wot-src-eu (wot-eu).
Контракты: IHangarSpace, ClientSelectableCameraVehicle, HangarVehicleAppearance,
CollisionComponent.getBoundingBox, TankNodeNames.GUN_JOINT,
GUI.HangarVehicleMarker/WGHangarVehicleMarker, Math.MatrixProduct,
realm.CURRENT_REALM.
WoT использует обратный порядок проходов из исходного DrawerController.
Runtime тестируется через MCP WotStat REPL 1.4.1 в MT 1.45 и WoT EU 2.4.
